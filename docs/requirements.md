## 1. プロジェクト概要

### 1.1 目的
「AIと学ぶ実践Web技術講座」の学習フェーズを支援するWebアプリケーション。学習コンテンツの配信、進捗管理、課題提出の機能を提供する。

### 1.2 関連事業
生成AI活用Web技術学習支援事業（2026年4月開講予定）

### 1.3 システム構成

本サービスは独立したWebアプリケーションとして運用される。認証・ユーザー管理も本アプリ内で完結する。

| サービス | 役割 | URL（開発環境） |
|:--|:--|:--|
| 学習支援サービス（本アプリ） | 認証、ユーザー管理、学習コンテンツ配信、進捗管理、課題提出 | `http://localhost:3000` |

## 2. ユーザー種別と権限

### 2.1 ユーザー種別

| 種別 | DB上のロール | 説明 |
|:--|:--|:--|
| 受講生 | `member` | コンテンツ閲覧、進捗管理、課題提出を行う |
| 講師 / 運営 | `maintainer` | コンテンツ管理（CRUD）を行う |
| システム管理者 | `admin` | 全権限を持つ |

### 2.2 ユーザーステータス

| ステータス | 説明 |
|:--|:--|
| `trial` | 承認待ち = **お試し（trial）ユーザー**。ログインしてサービスを利用できるが、閲覧・提出できるのはお試し公開コンテンツ（`is_open_to_trial = true`）のみ。承認待ちであることはアプリ内バナーで通知する |
| `active` | 承認済み（学習サービスに制限なくアクセス可能） |
| `rejected` | 却下済み（`/rejected` 却下画面へリダイレクト） |

お試しユーザーへの制限の詳細は「3.2 学習コンテンツ配信」および[機能設計書](./specification.md)2.6を参照。

### 2.3 権限一覧

| 機能 | 受講生 (member) | 講師 / 運営 (maintainer) | システム管理者 (admin) |
|:--|:--:|:--:|:--:|
| コンテンツ閲覧 | ○ | ○ | ○ |
| 自分の進捗確認 | ○ | ○ | ○ |
| 課題提出 | ○ | ○ | ○ |
| 提出履歴の確認 | ○ | ○ | ○ |
| コンテンツ管理（CRUD） | - | ○ | ○ |
| 受講生一覧・進捗一覧 | - | - | ○ |
| 提出課題の一覧確認 | - | - | ○ |
| 管理ダッシュボード | - | - | ○ |

上表はロール（`role`）による権限を示す。これとは別に、ステータス（`status`）による制限が重なる: お試しユーザー（`trial`）は「コンテンツ閲覧」「課題提出」「自分の進捗確認」の対象がお試し公開コンテンツのみに制限される。`active` は上表のとおり制限を受けない。

## 3. 機能要件

### 3.1 認証・ユーザー管理
- Googleアカウントによるログイン（Supabase Auth、本アプリ独自のSupabaseプロジェクト）
- 本アプリ内にログインページ・承認フローを実装
- 初回ログイン時にユーザーを自動登録（`status=trial`）し、そのままダッシュボードへ遷移。承認前でもお試しユーザーとしてサービスを利用できる
- プロキシ（`proxy.ts`）によるページ単位のアクセス制御
- 管理者向けユーザー管理画面（承認・却下・ロール変更操作）
- 初回ログイン時に指定Slackチャンネルへ承認依頼通知を送信（Slack Incoming Webhooks）

### 3.2 学習コンテンツ配信

#### コンテンツ構成（4階層）
```
Theme（例：GAS学習）
  └── Phase（例：Phase 1 - GAS基礎）
        └── Week（例：Week 1 - はじめの一歩）
              ├── 動画教材（複数）
              ├── テキスト教材（複数）
              ├── スライド（複数）
              └── 演習課題（複数）
```

#### コンテンツ種別
| 種別 | 表示方法 |
|:--|:--|
| 動画（video） | YouTubeの限定公開動画を埋め込み表示 |
| テキスト（text） | Markdown形式で記述・表示（GFM対応） |
| スライド（slide） | PDFファイルをブラウザ上に表示（Supabase Storage経由） |
| 演習（exercise） | Markdown形式の演習指示を表示、課題提出フォームと連携 |

#### コンテンツ表示制御
- `is_published` フラグで公開 / 非公開を制御
- `is_open_to_trial` フラグでお試しユーザーへの公開 / 非公開を制御（コンテンツ管理画面のチェックボックス「お試しユーザーにも公開する」で設定）
- `is_deleted` フラグで論理削除（データ保全）
- `display_order` で表示順を制御

#### お試しユーザーへの表示制御
- コースツリー（テーマ / フェーズ / 週 / コンテンツ一覧）は全件表示し、お試し非公開のコンテンツは鍵アイコンでロックする（何が学べるかを見せて入会動機につなげるため）
- ロック画面・フェーズ一覧・ダッシュボードで有料会員の価値訴求と本登録導線（`/upgrade`。Stripe無効時は承認の案内）を示す
- ロック済みコンテンツは中身を表示しない（直リンクでもロック画面）。進捗率の分母はお試し公開コンテンツのみ。承認前の提出・進捗は承認後も引き継がれる（詳細は[機能設計書](./specification.md)2.6）

### 3.3 進捗管理
- 各コンテンツに「完了」ボタンを配置
- 受講生が手動で完了 / 未完了をトグル
- ダッシュボードに全体・Phase単位・Week単位の進捗率を表示
- 管理者は受講生一覧で各受講生の進捗率・最終アクティビティを確認可能

### 3.4 課題提出
- **コード提出**: GASコードをテキストエリアに貼り付け
- **URL提出**: スプレッドシート / GASプロジェクト / デプロイ済みアプリのURL共有
- 提出方法は演習コンテンツごとに設定可能（コードのみ / URLのみ / 両方から選択）
- 提出履歴を一覧で確認可能
- 点数・合否判定は行わない
- 提出期限は目安のみ（強制なし）

### 3.5 AIレビュー機能
- 演習コンテンツへのコード提出に対して、Gemini APIによる自動レビューを実施
- レビューはコンテンツの演習指示・模範回答を参照して採点・フィードバックを生成
- レビュー結果（`ai_reviews` テーブル）は提出履歴画面で受講生が確認可能
- レビューのステータス管理: `pending` → `processing` → `completed` / `failed`

### 3.6 管理機能
- **管理ダッシュボード**: テーマ数、フェーズ数、週数、コンテンツ数、受講生数、提出数の統計表示
- **テーマ管理**: Theme の CRUD操作（最上位カテゴリ、サムネイル画像設定可）
- **コンテンツ管理**: Phase / Week / コンテンツのCRUD操作（PDFスライドのアップロード対応）
- **受講生管理**: 全受講生の進捗一覧、最終アクティビティ追跡
- **提出管理**: 全受講生の提出一覧表示

### 3.7 初回利用ガイド
- 初回1回だけ表示するウェルカムダイアログ（`/` ダッシュボード、`role = member` かつ `users.onboarding_completed_at IS NULL` のとき）
- ダッシュボードに常設するはじめかたチェックリスト（未達成がある `role = member` のときのみ表示、全達成で非表示）
- 対象は `role = member` のみ（`trial` / `active` の両方）。`admin` / `maintainer` には表示しない
- 記録先は `users.onboarding_completed_at`（TIMESTAMPTZ、NULL許容）。チェックリストは既存データからの自動判定のみで永続化しない

### 3.8 メール通知（受講生向け）
- 受講生の状態が変わったときに、本人へトランザクションメールを送る（送信プロバイダは Resend、送信元は返信不可の `noreply` アドレス）
  - **登録**: 初回登録時。お試しでできること、最初の学習コンテンツへのリンク、本登録（承認・アップグレード）の案内
  - **承認**: 管理者が承認したとき。本登録の完了と会員種別
  - **有料会員化**: Stripe 決済で一般有料会員になったとき。料金（実請求額）・次回請求日・お支払い管理の案内
  - **解約予約**: 期間末での解約を受け付けたとき。利用期限と、期限までに取り消せること
  - **有料会員の終了**: 解約等でお試しユーザーに戻ったとき。お試しコンテンツは引き続き使えることと再開方法
- 同一事象のメールは1通だけ送る（決済反映の複数経路・Webhook の再送でも重複させない）
- メール送信の失敗・未設定は、登録・承認・決済などの主処理の結果に影響させない
- 却下通知・支払い失敗の受講生向け通知（Stripe の自動メールに任せる）・AIレビュー完了通知は送らない
- 案内系メールは既存の利用規約への同意（ログイン画面）に基づく。追加の同意項目は設けない
- 受講生（`role = member`、`trial` / `active`）へ、案内系の定期メールを毎朝のバッチで送る
  - **週次進捗**（毎週月曜が初期値）: 先週の完了数・提出数、次に学ぶコンテンツ（未完了の先頭）へのリンク、今週の目標の提案
  - **未学習リマインド**（登録から7日目・14日目が初期値）: 進捗も提出も無いユーザーに、最初の1本へのリンクと困ったときの連絡先
  - **お試しユーザー向け案内**（登録から2・5・7・14日目が初期値）: 演習の提出 → AIレビュー → 本登録で学べる内容とアップグレード（決済機能が有効なときのみ）→ 最後の案内。未学習リマインドと同じ日は、こちらを優先する
- 案内系メールには必ずワンクリックの配信停止リンクを入れる（ログイン不要）。配信停止はトランザクションメールには影響しない。再開は管理者が行う
- 1日のバッチで送る通数に上限を設け（初期値80通。Resend の日次上限対策）、週次進捗の超過分は同じ週の翌日以降に送る
- お知らせ（3.9節）で「メールでも送る」を選んだものは、毎朝のバッチでメールでも一斉送信する（案内系メールと同じく配信停止を尊重し、1日の上限を超える分は翌日以降に分けて送る）

#### メール通知の管理（管理者のみ）
- 管理者（`admin`）が管理画面から、開発者を介さずにメール通知を調整できる。全受講生への送信にかかわるため、`maintainer` には開放しない
  - **種別ごとの有効・無効**: 登録・承認・有料会員化・解約予約・有料会員の終了・週次進捗・未学習リマインド・お試しユーザー向け案内・お知らせの一斉送信
  - **送るタイミング**: 未学習リマインド・お試しユーザー向け案内は「登録から N 日目」、週次進捗は曜日（送信時刻は対象外。Cron の起動時刻は `vercel.json` で固定）
  - **案内系メールの1日の上限**
  - **送信履歴**: 日時・種別・宛先・状態（送信済み / 失敗 / 未完了）・失敗時のエラーを新しい順に確認し、種別と状態で絞り込める。メール本文は保存しない
  - **配信停止の管理**: ユーザー管理で、配信停止の状態を確認し、本人の依頼に応じて停止・再開できる
- 初期値は既存の挙動（すべて有効、送る日・曜日・上限は従来どおり）と同じ
- 設定を読めないときは、案内系メールは送らず（フェイルクローズ）、トランザクションメールは送る（登録・決済の通知を欠落させないため）
- 画面からの即時送信・手動実行は設けない（Resend の日次上限と二重送信の制御を Cron に一本化するため）

#### メール文面の編集（管理者のみ）
- 管理者（`admin`）が管理画面から、開発者を介さずに受講生向けメールの文面を編集できる（コードの変更・デプロイは不要）
  - **サービス名**: 差出人名・件名の先頭（`【サービス名】`）・本文の見出し・フッターの名前と、見出しの補足・フッターに添える講座名。既定値は「Sinlab Study」と「AIと学ぶ実践Web技術講座」
  - **各メールの件名と本文（Markdown）**: 登録・承認・有料会員化・解約予約・有料会員の終了・週次進捗・未学習リマインド・お試しユーザー向け案内（2・5・7・14日目の段階ごと）・お知らせの一斉送信。お知らせの本文自体はお知らせごとに編集するため、テンプレートで扱うのは前後の定型文だけ
- 金額・日付・学習の実績・コンテンツ名など、状況で変わる部分は、システムが計算した値を本文の `{{プレースホルダー}}` に差し込む。テンプレートごとに使えるものが決まっており、それ以外を含む文面は保存できない
- 編集できないもの（コードで固定）: 宛名（「〇〇 様」）、ボタンのリンク先と表示条件、自動送信・返信不可の定型文、配信停止リンクと配信停止ヘッダー、送信の条件・タイミング（法令上の必須表示と送信の制御に関わるため）
- 画面で、保存前の入力内容のプレビュー（テキスト版・HTML版。条件の切り替えつき）、自分宛のテスト送信（1日の回数に上限）、「既定に戻す」ができる
- 文面を読めないときは、その種別を既定の文面で送る（登録・決済の通知や定期メールを止めない）。文面の変更履歴（版管理）は持たない

### 3.9 お知らせ機能
- 運営（admin / maintainer）が受講生へお知らせを出す（もくもく会などのイベント・新コンテンツの告知。Study 一般会員へのサロンの案内などにも使える）
- 管理画面（`/manage/announcements`）でお知らせを作成・編集・公開・削除（論理削除）する。本文は Markdown
- 対象はステータス（本登録 / お試し）と会員種別（全種別、またはコミュニティ会員・一般有料会員）で指定する。会員種別を指定したお知らせはお試しユーザーには見えない
- 受講生はダッシュボードで未読のお知らせ（最大3件）を、`/announcements` で一覧と詳細を見られる。詳細を開くと既読になり、サイドナビに未読件数を表示する
- 対象外のお知らせ（下書き・削除済み・対象外のステータス・会員種別）は、タイトルを含めて受講生に見せない
- 「メールでも送る」を選んだお知らせは、画面から即時には送らず、公開後の毎朝のバッチでメールでも一斉送信する（3.8節）

## 4. 画面一覧

### 4.1 受講生向け画面

| パス | 画面名 | 概要 |
|:--|:--|:--|
| `/` | ダッシュボード | 全体進捗率、Phase別進捗バー、学習への導線、初回ガイド・はじめかたチェックリスト、未読のお知らせ（最大3件） |
| `/learn` | テーマ一覧 | 公開Themeのカード一覧 |
| `/learn/[themeId]` | Phase一覧 | Theme内のPhase一覧、進捗表示 |
| `/learn/[themeId]/[phaseId]` | Week・コンテンツ一覧 | Phase内の各Weekとそのコンテンツを一覧表示、進捗表示 |
| `/learn/[themeId]/[phaseId]/[weekId]/[contentId]` | コンテンツ詳細 | 動画/テキスト/スライド/演習の表示、完了ボタン、課題提出 |

| `/announcements` | お知らせ一覧 | 自分が対象の公開済みお知らせ（未読表示付き） |

### 4.2 管理・講師向け画面（`/manage`）

admin と maintainer（講師）が共通でアクセス可能。`/admin` 配下のコンテンツ管理ページ（`/admin/themes`・`/admin/phases`・`/admin/weeks`・`/admin/students`・`/admin/submissions` および `/admin` ルート）と `/instructor` へのアクセスは `/manage` 配下にリダイレクトされる。ユーザー管理（`/admin/users`）は管理者専用で、リダイレクトされない（4.3参照）。

| パス | 画面名 | 概要 |
|:--|:--|:--|
| `/manage` | 管理ダッシュボード | 統計サマリー、最近の提出一覧 |
| `/manage/themes` | テーマ管理 | ThemeのCRUD（サムネイル画像設定含む） |
| `/manage/phases` | フェーズ管理 | PhaseのCRUD |
| `/manage/weeks` | 週管理 | WeekのCRUD |
| `/manage/contents` | コンテンツ管理 | コンテンツのCRUD（PDFスライドアップロード含む） |
| `/manage/students` | 受講生一覧 | 全受講生の進捗率、最終アクティビティ |
| `/manage/submissions` | 提出管理 | 全提出一覧 |
| `/manage/announcements` | お知らせ管理 | お知らせの作成・編集・公開・削除、メール送信の状況 |

### 4.3 管理者専用画面

| パス | 画面名 | 概要 |
|:--|:--|:--|
| `/admin/users` | ユーザー管理 | ユーザー一覧、承認・却下・ロール変更操作、案内メールの配信停止状態の確認と停止・再開 |
| `/admin/emails` | メール通知 | メール種別ごとの有効・無効・送信タイミングの設定、案内系メールの1日の上限、今日の送信状況、送信履歴 |
| `/admin/emails/templates` | メール文面の編集 | サービス名の編集、メール文面（件名・本文）の一覧、編集画面（プレースホルダー一覧・プレビュー・既定に戻す・テスト送信） |

## 5. 非機能要件

### 5.1 対応デバイス
- **PC**: メイン利用を想定、フル機能
- **スマートフォン / タブレット**: レスポンシブ対応（モバイルドロワーナビゲーション）

### 5.2 パフォーマンス
- 初期受講生規模：10〜20名
- Supabase / Vercel無料枠で対応可能な範囲
- Server Componentsによるサーバーサイドレンダリング
- 並列データ取得による高速化

### 5.3 セキュリティ
- Supabase Authによる認証
- プロキシ（`proxy.ts`）によるページ単位のアクセス制御
- Row Level Security（RLS）によるデータベースレベルのアクセス制御（お試しユーザーへのコンテンツ制限はアプリ層とRLSの二層で担保）
- Markdown表示は react-markdown のデフォルト動作（生HTMLタグを描画しない）によりXSSを防止
- 認証セッションからユーザーIDを導出（API操作時、クライアント送信値では認可しない）
- 独立認証基盤: 本アプリ独自のGoogle OAuth + ユーザー承認フロー（詳細は[機能設計書](./specification.md)のセクション2を参照）

### 5.4 ダークモード対応
- `prefers-color-scheme` によるOS設定連動のライト / ダークモード切り替え
- 例外: 未認証画面（`/login`・`/demo` 配下・`/rejected`）はOS設定にかかわらず常にライト表示（初見ユーザーの不安軽減・LPとの一貫性）
- CSS変数によるテーマカラー管理
